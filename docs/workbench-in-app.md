# 在客户端内打开「资源工作台」— 设计方案

> 目标：普通账户登录客户端后，能在客户端自己的窗口里使用 dashboard（资源工作台）的全部功能，而不是被甩到系统浏览器。
> 状态：**待评审**（未实现）。评审通过后按第 7 节的阶段落地。

---

## 1. 结论先行

**不重写工作台，直接在工作台窗口里承载 web 端页面。**

工作台的业务量（环境/服务器/Redis/项目/Nacos、WebSocket 终端、构建记录、收藏栏）远超一个客户端面板能重画的范围，而 web 端本身是**服务端渲染 + HTMX**，天然就是"能直接装的成品"。真正需要设计的不是功能，而是**接缝**：从哪进来、窗口长什么样、会话失效怎么办、怎么不闪白屏。

客户端现有的 `open_dashboard` → `open_browser` 链路**已经完成了 90% 的准备工作**（见第 3 节），本次改动主要是把"交给系统浏览器"换成"交给客户端自己的第二扇窗"。

---

## 2. 后端事实（来自 fw-devops 仓库实测）

| 事实 | 说明 |
|---|---|
| 技术栈 | Java 21 + Spring Boot 3.3.5，Thymeleaf + HTMX 2.0.3 + Alpine + Tailwind CDN + daisyUI |
| `/dashboard` | 普通账户资源工作台：环境切换 + 服务器 / 缓存 / 项目 / 注册中心 四类资源 + 收藏栏 + 构建记录弹窗 |
| 普通账户 vs 管理员 | `/dashboard*` 本身不区分账户类型；区分体现在权限码白名单（`server:` `redisCache:` `deployProject:` `buildRecord:` `nacos:` `dbWorkbench:` 等）。普通账户看不到管理侧边栏，用的是工作台自带的"环境与资源"导航 |
| 会话 | 自研 Session，Cookie `SESSION_ID`（`HttpOnly` + `SameSite=Lax` + 生产 `Secure`），服务端存 Redis，滑动 120 分钟 + 绝对 8 小时 |
| 一次性票据 | `POST /api/auth/create-exchange-token` → 5 分钟 TTL、兑换即焚；浏览器侧 `GET /api/auth/exchange-token?exchangeToken=...` 兑换后建 `wb.` 会话并 302 到 `/dashboard` |
| 设备证明 | 工作台页面用 WebCrypto 生成不可导出密钥、签名心跳（30s），challenge/nonce 由兑换链路下发 |
| **响应头（关键约束）** | `X-Frame-Options: DENY` + CSP `frame-ancestors 'none'` → **iframe 内嵌走不通**；但**顶层导航不受限制** |
| 主题 | `tokens.css` 多套主题，默认 `idea`（暗色）；`--bg-primary: #0B1120`、`--accent-cyan: #00E5FF` 与桌面客户端**完全同源** |

两条直接推论：

1. **绝不能走 iframe / 在主窗口里塞 webview**（`frame-ancestors 'none'` 会拒绝，而且主窗口只有 360px 宽）。
2. **顶层导航 + 独立窗口**是唯一正确解法，且不需要服务端改任何代码。

## 4. 方案

### 4.1 打开链路

见对话中的链路图。要点：

1. 点击入口 → 窗口已存在则直接聚焦（**单例**），否则进入第 2 步。
2. Rust 侧签发一次性票据（复用现有实现）。
3. **窗口以 `visible: false` 创建**，先把窗口底色设成 `#0B1120`，再顶层导航到兑换地址。
4. 服务端兑换票据 → 建会话 + 下发设备证明引导数据 → 302 `/dashboard`。
5. **页面加载完成（`PageLoadEvent::Finished`）后才 `show()`**，并设 3s 兜底显示。

### 4.2 为什么必须"先建窗口再显示"

这是本项目踩过的坑的正面用法：远端页面首帧是白的，窗口一显示就会闪白。三层防护：

- 窗口底色 = `#0B1120`（`set_background_color`；**Windows 上此时反而是正确做法**——那条路径要的就是不透明深色）
- 页面加载完成前 `visible: false`
- 加载慢也不至于让人以为没反应：1.5s 兜底 show

### 4.3 窗口形态

| 项 | 取值 | 理由 |
|---|---|---|
| 边框 | **内容铺满**（`decorations(true)` + `TitleBarStyle::Overlay`），主题锁 `Dark` | 让**网页自己的顶部导航承担标题栏职责**，红绿灯悬浮其上，左侧留灯位。这样只剩"一层天空"，不再有"系统条 + 网页条"的套壳特征（见 4.7） |
| 兜底 | 若 4.7 的 `embed` 契约暂时不具备，可退回**原生边框**（`decorations(true)` 普通样式） | 退回时接受"两层天空"，属于临时妥协而非终态 |
| 尺寸 | 默认 1180×760，最小 960×620，居中于主窗口所在屏 | web 端在此宽度下是"侧栏 + 四类资源卡"的舒适布局 |
| 标题 | `资源工作台`（DEV 构建加 ` [DEV]`，与主窗口一致） | Overlay 下原生标题文字必须置空，否则与网页导航叠成重影（主窗口踩过同样的坑） |
| 圆角/阴影 | 交给系统 | |
| 打开动效 | 不做窗口级动画（`visible:false → show` 本身就是"瞬时出现"） | 自绘窗口动画在各平台代价高、收益低 |

### 4.4 与主窗口的关系

- 主窗口**保持可见**（继续显示心跳/运行状态），不隐藏、不切换。
- 关闭工作台窗口 = 只关这一扇窗，**不等于退出客户端**（主窗口的关闭仍是隐藏到托盘）。
- 工作台窗口关闭后把焦点交回主窗口。

### 4.5 会话失效与异常态

| 落点 | 处理 |
|---|---|
| 302 到 `/dashboard` | 正常，加载完成后显示 |
| 落到 `/login` | **关闭工作台窗口 + 面板提示**（不静默续期）。原因见下 |
| 落到 `/workbench-offline` | 设备在场标记丢失（通常是客户端心跳中断）。提示"设备心跳中断，正在重连"并触发一次静默续期 |
| 落到 `/workbench-closed` | 用户从 web 端点过退出 → 直接关闭工作台窗口 |

> **为什么 `/login` 不静默续期**：落到登录页有两种原因 —— 会话超时，或用户**主动**在网页上退出登录。
> 把主动退出的用户"自动登回去"比不续期更糟（用户会以为退不掉），所以这里只关窗 + 提示；
> 用户需要时从面板重新打开，那条路径会签发新票据，一样是瞬时的。
| 网络不可达 | 走已有的加载失败提示：Rust 侧检测加载错误 → show 窗口并显示客户端自绘的错误页（`#0B1120` 底 + 重试按钮），而不是浏览器的白色错误页 |

### 4.6 安全边界（重要）

- 工作台窗口加载的是**远端页面，不是我们的代码** → **不授予任何 IPC 权限**（capabilities 里不要加这个窗口）。窗口的创建、URL 监听、关闭全部由 Rust 侧驱动。
- 客户端自己的 CSP（`default-src 'self'`）只作用于本地页面，不限制这扇窗；远端页面受服务端 CSP 约束。
- Cookie 由 WebView 自身的数据目录持久化，但**每次打开仍走一次性票据**——因为设备证明的 challenge/nonce 必须由兑换链路下发，直接访问 `/dashboard` 拿不到引导数据。
- 关闭窗口时的 `workbench-disconnect`：优先让页面自身的 `beforeunload` 处理；Rust 侧可在窗口关闭时兜底（读 webview cookie 取 `SESSION_ID` 后 POST），服务端的证明 TTL（90s）是最后兜底。

---

### 4.7 反套壳感：让两端协同（本方案的关键）

**风险**：直接把网页塞进一扇原生窗口，会呈现三个"套壳破绽"——① 系统标题栏 + 网页顶部导航叠成"两层天空"；② 两套视觉语言（字体/圆角/阴影/动效）各说各话；③ 窗口里没有任何客户端元素，用户看不出这是客户端开的，也看不出设备状态。

**破绽的本质**：不是"承载了网页"，而是"没有任何客户端痕迹"。浏览器打开同一个工作台时，这三个破绽一个都不会出现。

**最大的一张牌：后端也是自有仓库**（`fw-devops`），所以可以让网页**主动配合**，而不是被动被包起来。

### 4.7.1 契约：`?embed=client&v=1`

客户端在兑换链接上带 `embed=client`（随 302 落到 `/dashboard` 的 URL 上），网页侧在 embed 模式下做四件事：

| 网页侧改动 | 作用 | 对应破绽 |
|---|---|---|
| `<body class="client-embed">` | 客户端环境的样式钩子 | ② |
| 顶部导航左侧留出灯位（约 76px） | 红绿灯直接压在导航上，不再叠一层 | ① |
| 渲染空的 `#client-status-slot` | 客户端往里注入"设备已证明 / 心跳 / 客户端版本" | ③ |
| 启用 `client` 主题（对齐客户端 token） | 字体、圆角、间距、动效同一套 | ② |

契约要**版本化**（`v=1`）：网页改版时客户端能感知并降级（降级 = 退回原生标题栏），不会静默错位。

### 4.7.2 客户端侧的三件事

1. **状态位注入**：Rust 侧 `webview.eval()` 往 `#client-status-slot` 写客户端本地状态（设备指纹短码、心跳、版本）。这是浏览器打开时**不可能有**的信息，也是"这是客户端"最直接的证据。
2. **兜底降级**：注入点不存在（网页版本不匹配）时，不报错、不重试，退回原生标题栏形态。
3. **两端联动**：工作台心跳异常 → 主窗口的球转琥珀；关闭工作台 → 主窗口接回焦点并播一次"收回"微动效。让用户感到"两扇窗是一个东西"。

### 4.7.3 如果后端暂时不配合

可以只用客户端单侧手段暂顶：`Overlay` + Rust 注入一小段 CSS 给导航加左内边距。**不推荐作为终态**——注入别人的 DOM 天然脆弱，网页一次改版就会错位，而 `embed` 契约是双方共同维护的稳定接口。

### 4.7.4 另一条路线：原生工作台（精选功能）

如果目标不是"用上 dashboard"，而是"看起来、用起来都是一个客户端"，那还有一条路：**不承载网页，用客户端自己的 UI 重做普通账户最常用的几个动作**（收藏的服务器状态、一键打开终端、快速部署、构建记录），走普通账户可用的 JSON API（`/servers/*`、`/api/deploy-projects/*`、`/api/dashboard/build-records/*`、WS 终端）。这条路的取舍：

- 优点：100% 不是套壳，与客户端完全同源，离线感更好
- 代价：要重写交互编排（环境切换、权限差异、片段刷新），且**工作台的长尾功能仍然只能去浏览器**
- 现实定位：**不是替代方案，而是可选的第一屏**——原生面板覆盖高频动作，深度操作用融合式工作台窗口接住

| 入口 | 行为 |
|---|---|
| 监视球**单击** | 内置工作台窗口（默认；原行为是开系统浏览器） |
| 监视球**长按** | 复制链接（不变） |
| 面板「工作台」按钮 | 同单击 |
| 设置项「打开方式」 | `内置窗口`（默认）/ `系统浏览器` —— 保留退路，也给多屏/远程桌面场景留选择 |

**阶段 2 可选深链**：从面板直接进入某台服务器的终端（web 端已支持 `?envId=` 的 HTMX 局部刷新），但需要先确认可用的 URL 参数，属增强项。

## 5. 入口设计

### 5.1 新增设置组「启动与打开」

| 设置 | 取值 | 默认 |
|---|---|---|
| 登录后 | 停在状态面板 / 直接打开工作台 | **停在状态面板**（= 现有行为，不改老用户） |
| 打开方式 | 内置窗口 / 系统浏览器 | 内置窗口 |

**命名注意**：不要叫「代理客户端 / 本地客户端」，也不要叫「模式」。代理能力（心跳、设备在场、设备证明）在两种落点下**都在跑**——这是"登录后的落点偏好"，不是产品形态。叫"模式"会让人以为关掉代理，或者以为自己在用两个不同的产品。

**联动规则**（两项必须互相约束）：

- 选「直接打开工作台」→「打开方式」自动锁定为「内置窗口」；反之选「系统浏览器」→「登录后」自动回到「停在状态面板」
- 不成立的组合在 UI 上直接置灰，不允许配置出"登录后被甩到外部浏览器"这种割裂体验

### 5.2 触发规则（什么时候算"登录后"）

| 场景 | 是否按设置打开 |
|---|---|
| 手输账号密码登录成功 | 是 |
| 启动时的指纹免密续登（auto-login） | 是（启动是用户发起的） |
| **从托盘 / 隐藏状态恢复显示主窗口** | **否** —— 那是"唤醒"，不是"登录" |
| 登出后再登录 | 是 |
| 将来若加开机自启 | **否**，自启路径强制停在状态面板 |

最后一条是预留钩子：当前客户端**没有**开机自启功能（无 autostart 插件），但"常驻代理"迟早会要求它，而每次开机弹出一个 1180×760 的大窗口正是这类工具最典型的差评来源。现在就把这个例外写进设计，比以后改行为便宜。

### 5.3 入口

| 入口 | 行为 |
|---|---|
| 监视球**单击** | 按「打开方式」打开工作台 |
| 监视球**长按** | 复制链接（不变） |
| 面板「工作台」按钮 | 同单击 |

自动打开工作台时，**主窗口保持可见、不自动隐藏**（代理状态与心跳异常提示都在那里），由工作台窗口持有焦点。

**阶段 2 可选深链**：从面板直接进入某台服务器的终端（web 端已支持 `?envId=` 的 HTMX 局部刷新），但需要先确认可用的 URL 参数，属增强项。

## 6. 为什么不做「原生 UI 重画整个工作台」

（注意与 4.7.4 的区别：那条讲的是**用原生面板覆盖高频动作**，是可选的第一屏；这里讲的是**把工作台整体重画一遍**，不可取。）

| 方案 | 否决理由 |
|---|---|
| 用客户端原生 UI 重画工作台 | 等于把 web 端整个前端重写一遍（含 WebSocket 终端、Redis 工作台、DB 工作台、Nacos、Jenkins 部署），维护两套 UI 且必然长期不同步 |
| iframe / 主窗口内嵌 webview | 服务端 `X-Frame-Options: DENY` + `frame-ancestors 'none'` 双重拒绝；而且主窗口 360px 宽，装不下工作台 |
| 直接调 JSON API 做轻量工作台 | 普通账户可用的 JSON API 不少，但"能用"的体验都依赖 web 端的交互编排（环境切换、片段刷新、终端）。可作为阶段 3 的"面板内联卡片"（如收藏的服务器状态），不是替代方案 |

## 7. 落地阶段

**阶段 1 — 客户端单侧（已实现）**

1. Rust：`open_workbench_window`（单例 + 隐藏创建 + 底色 + 导航 + 加载完成显示 + 兜底显示 + 关闭清理）
2. Rust：URL 落点监听（`/login`、`/workbench-*`）与会话静默续期
3. 前端：面板入口改为内置窗口；设置项「打开方式」
4. 文档：CLAUDE.md 补「第二扇窗的约定」（禁止给它 IPC 权限、底色必须预设、单例语义）

> 阶段 1 的 macOS 走 `Overlay` + 注入一小段 CSS 给导航让出灯位（`WORKBENCH_INSET_SCRIPT`，
> 只用一个 daisyUI 稳定类名 `.navbar`）。**这是临时手段**，embed 契约落地后应删掉。
> Windows / Linux 仍是原生边框 —— 与 macOS 不同，Windows 上带标题栏是常态，套壳感远弱于 macOS。

实测（2026-10-15，macOS 真机 + 模仿 dashboard 结构的替身页）：窗口 1180×761，内容铺满到窗顶，
红绿灯悬浮在网页导航上、品牌名从灯右侧开始、零重叠；主窗口同时保持可见。

**阶段 2 — 反套壳（需要后端配合，是本方案的精华）**

5. `fw-devops` 侧：支持 `?embed=client&v=1`（body class、导航左留灯位、`#client-status-slot`、`client` 主题）
6. 客户端侧：状态位注入（设备证明/心跳/版本）+ 注入失败自动降级为原生标题栏形态
7. 两端联动：工作台心跳异常 → 主窗口球转琥珀；关闭工作台 → 主窗口接回焦点并播"收回"微动效

**阶段 3（可选）**
- 窗口尺寸/位置记忆；自绘错误页（网络不可达 / 服务端 5xx）；深链到具体资源
- 面板内联"收藏服务器"状态卡（原生 UI + JSON API，作为可选第一屏，见 4.7.4）

## 8. 验证清单

| 项 | 怎么验 |
|---|---|
| 打开无白闪 | 录屏/连拍；macOS 与 Windows 各一次（Windows 这条路径窗口不透明，底色设置是必需项） |
| 单例 | 连点 5 次，只应有一个窗口，且已被聚焦 |
